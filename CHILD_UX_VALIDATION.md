# Child Dashboard UX Validation

Prototype route: `/kid`

The prototype was checked against the project requirements and child-centered heuristics rather than copying adult dashboard patterns.

- Navigation uses four concrete destinations with icons and plain labels; mobile keeps them in a horizontally scrollable landmark.
- The primary action is a single resumable mission. Secondary levels, quiz, Blockly practice, rewards, and profile remain discoverable without competing for first attention.
- Progress is described with words and accessible progress semantics. XP and rewards acknowledge effort but do not use countdown timers, streak loss, leaderboards, or social comparison.
- Quiz language explicitly permits retrying. The welcome message says there is no timer, reducing speed pressure.
- Controls use large touch targets, visible keyboard focus, short sentences, and status text in addition to color.
- Blockly is represented as a spatial workspace with a small nested sequence, keeping the conceptual load appropriate for an early prototype.
- Parent and admin actions are absent from child navigation. Profile settings are visually secondary.
- The layout collapses to one column on small screens and preserves the same reading order as the document structure.

This is a conceptual prototype; usability sessions with children and guardians are still required before treating age fit, reward language, and comprehension as validated product policy.

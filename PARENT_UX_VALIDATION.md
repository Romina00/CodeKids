# Parent Dashboard UX Validation

Prototype route: `/parent`

- The first view answers three parent questions: which child is selected, how learning is progressing, and what meaningful activity happened recently.
- Multiple child profiles are visible without exposing one child&apos;s detailed activity inside another profile.
- Learning time is presented as a weekly aggregate, not surveillance-style minute-by-minute tracking.
- Progress, completed levels, and rewards use text and semantic structure in addition to color.
- The prototype avoids leaderboards, child comparisons, negative streaks, and prescriptive time targets.
- Reward guidance encourages parents to discuss learning strategy rather than badge accumulation.
- Family controls and privacy/security are visible but secondary to the learning summary.
- The mobile layout preserves reading order and turns multi-column summaries into a single column.

Profile permissions, reporting periods, time-spent definitions, notification policy, and the final parent vocabulary remain owner decisions. This prototype is a concrete review surface, not approval of those policies.

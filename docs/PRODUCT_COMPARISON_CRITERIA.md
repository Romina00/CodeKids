# Similar-product comparison framework

**Review date:** 2026-07-15  
**Scope:** CodeMonkey, Code.org, and ScratchJr as reference products for
CodeKids.

## Method and limits

This document defines a repeatable comparison framework and records a
source-backed desk-research snapshot. Product claims are based on the vendors'
official public documentation linked below. A human author must perform the
final research: validate the products hands-on, check regional availability and
current pricing, interview representative children and guardians, and approve
any thesis conclusions. A missing public feature is recorded as “not evidenced,”
not as proof that the feature does not exist.

## Comparison criteria

| Criterion         | Questions to answer                                                                                               | Evidence to collect                                            |
| ----------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Age fit           | What ages/grades and reading abilities are supported? Does complexity grow with the learner?                      | Published age range, course map, observed reading load         |
| Interaction model | Blocks, text, guided puzzles, open creation, or a mixture? Which devices are supported?                           | Product walkthrough and supported-device documentation         |
| Gamification      | Are there levels, challenges, narrative, rewards, avatars, or open-ended creation?                                | First-use observation and curriculum description               |
| Progress          | What is saved? Can an adult see completion, mastery, time, work, or feedback?                                     | Learner and adult dashboard walkthroughs                       |
| Parental control  | Can a guardian create/manage children, assign content, limit access, and review progress?                         | Guardian-account walkthrough and privacy documentation         |
| Accessibility     | Which languages, keyboard/screen-reader features, captions, themes, and non-reader accommodations are documented? | Accessibility statement/VPAT plus assistive-technology testing |
| Access model      | Is use free, subscription-based, account-free, online, or offline?                                                | Current plan page and install/connectivity test                |
| Learning design   | Is the path sequential or exploratory? Which concepts and programming representations are used?                   | Curriculum map and sample activity analysis                    |

For a human evaluation, score each criterion from 0 (not evidenced) to 4
(strongly demonstrated), attach a source or observation to every score, and
weight the criteria before testing. Do not infer a total score from this desk
review.

## Human validation protocol

1. Test the same beginner scenario on supported target devices with at least two
   children from each intended age band; obtain guardian consent.
2. Observe first-task completion, help requests, reading dependency, error
   recovery, and engagement without coaching the child toward a result.
3. Create the available adult account and verify child creation, assignment,
   progress visibility, privacy controls, deletion, and session restrictions.
4. Repeat key flows using keyboard-only navigation, screen reader, zoom/high
   contrast, reduced motion, and the intended Persian/English language setting.
5. Archive screenshots, plan/pricing region and date, task notes, and exact URLs;
   have the thesis author review scores and write conclusions independently.
